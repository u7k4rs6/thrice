thrice

A harness that answers whether a reported bug still reproduces, by running the reported steps three times in three browsers and checking typed predicates against backend state, rather than asking a model what it saw.

How it works

  1. Fork a Solari sandbox from a snapshot of the app at a pinned release, in about ten seconds.
  2. Seed backend state over OTLP/HTTP, then verify it is queryable before running anything.
  3. Run the reported steps in three independent browsers over CDP, concurrently.
  4. Check two typed predicates per run. A run counts as reproduced only if the actual predicate holds and the expected predicate fails. No model is in the run loop.

What it got wrong

#4045 False positive. The plan reaches the state in the issue, but the resizer read absent on both releases, so the internal side-panel flag is probably not satisfied by that state.

#3967 False negative. The bug did not manifest under the plan's steps. The two releases have materially different search UIs: the List/Table toggle does not exist in the older one.

#3468 Inconclusive. The compare route renders identically on both releases, so the URL-driven approach never reaches the state the bug needs.

These are kept in the count. Removing an entry after seeing its result is the one thing that would make the number meaningless.

What did not work

Running three times instead of once is the core of the design. On this corpus it bought nothing: 63 runs across 21 attempts produced zero divergence and zero FLAKY verdicts. Every attempt that completed did so unanimously.

That is not evidence the mechanism is worthless. The corpus was selected for entries reproducible from a small deterministic seed, which is close to selecting for non-flaky behaviour, and the excluded candidates include the timing-sensitive cases where flakiness would live. But the design was validated on a corpus chosen to make it redundant, and the divergence differ is left specified and unbuilt because there is nothing here for it to align.

What bounded the corpus

Of 44 candidate issues, 36 were excluded, and 22 of those failed on release-pair availability alone: the issue was fine, but the versions needed to check it against do not exist as buildable releases. Jaeger 2.x is published only for 2.14.0 through 2.20.0. That bounds any tool built this way, not just this one.

Built on Solari

Sandboxes run Jaeger 2.x all-in-one with no external backend. snapshot and create(from_snapshot=...) make an attempt cost seconds instead of a full build. preview_url exposes the UI so a cloud browser can reach it. Browsers are driven over raw CDP with unmodified Playwright, and Page.startScreencast produces the video above. Ten findings from the build, including several about the platform, are in findings.md.
